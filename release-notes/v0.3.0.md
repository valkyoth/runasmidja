# Runasmidja 0.3.0 — Workflow reference policy

Status: implementation candidate; maintainer pentest PASS; GitHub/tag pending. No push/tag.
Baseline: signed v0.2.3. All six crates are 0.3.0 and publish=false.

Replace regex-only workflow pin checks with a bounded YAML gate covering both
workflow suffixes, action and reusable-workflow references, containers and
explicitly reviewed same-repository composite actions/workflows. Detect quoted,
escaped, flow and block-scalar reference forms without treating comments, names
or ordinary strings as executed actions. Reject dynamic/unpinned references,
ambiguous YAML and local traversal/symlink/cycle failures.

The tooling-only PyYAML parser is pinned by version and wheel hashes, installed
in a private local environment and monitored for freshness. Run
`scripts/install_python_tools.sh` before the common gate on a new checkout.
No Rust runtime dependency, service image or production website feature is added.
Probe inventory version metadata follows the workspace version.

GitHub CI gains only the small parser install and policy regressions. Heavy
container qualification remains local; CodeQL stays Default. Remote content,
shell behavior, checkout mutation and deliberately malicious policy changes still
require trusted review. See the [policy and limits](../docs/WORKFLOW_POLICY.md).

Verification and exact candidate identity are recorded in the
[handoff](../docs/releases/v0.3.0-handoff.md) and
[assessment](../security/pentest/v0.3.0.md). Automated checks cannot attest PASS.
Maintainer accepted `fdaa486` with no new findings. Next: push the final release
commits, review GitHub, then an explicitly authorized signed tag. v0.4.0 feature/target admission remains a separate pass.

## First pentest remediation

One Low finding (SAST-001) identified the post-checkout enforcement boundary.
Enabled GitHub's platform full-SHA action policy and verified the live setting.
Added a read-only policy check and regressions for disabled/missing settings,
API failures and minimal bootstrap ordering. All three single-job workflows now
run policy validation immediately after checkout/parser setup. Reusable workflows
remain a reviewed boundary; future jobs require policy-job dependencies. No
administrative credential, extra CI job, push, tag or publishing step is added.
Maintainer retest accepted this remediation; see [assessment](../security/pentest/v0.3.0.md).
