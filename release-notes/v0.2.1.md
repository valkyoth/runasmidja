# Runasmidja 0.2.1 — Wolfi probe packaging

Status: implementation candidate; maintainer pentest NOT RUN.
Compatible packaging patch over signed v0.2.0; no new website/API behavior.

Add an optional minimal Wolfi static runtime for the existing Rust health probe.
Public base admission verifies its signed index, selected Linux/amd64 digest,
current exact-image scan and inventory. The local image uses the locked Rust
1.99.0 static musl executable, with COPY-only offline assembly and no package
installation. Its scanned archive is bound by config/layer digests; the executable
copied from the created container must match the built executable hash.

Actual runtime qualification checks UID/GID, image/entrypoint, read-only root,
no-new-privileges, zero capabilities, memory/swap/PID/CPU restrictions, an
OS-selected loopback port, health and rejected routes/methods. Unique captured
container IDs/labels govern cleanup. Native/scratch profiles are retained.
Regression tests cover changed archive bytes, scanner admission, executable and
configuration mismatch, kernel limits, ownership and failed runtime cleanup.

Heavy builds/scans/runtime tests remain local pre-push work. GitHub retains code
checks and CodeQL Default setup. All six first-party crates are version 0.2.1,
publish=false; no external Rust dependency was added.

Limits: Linux/amd64 only; trusted-host build custody, not reproducible or signed
published image provenance. Scanner OS inventory does not attest stripped Rust
internals; Cargo SBOM/audit and executable hashes are separate evidence. No
production HTTP, browser/recipe execution, service migration or image publication
is added. OpenBao's existing review still expires 2026-11-02. Valkey/OpenBao Wolfi
follow-ups remain separate proposed patches. See the
[scope](../docs/releases/v0.2.1-scope.md) and [assessment](../security/pentest/v0.2.1.md).
