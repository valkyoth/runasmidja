# Runasmidja 0.2.2 — Wolfi Valkey fixture

Status: implementation candidate; maintainer pentest NOT RUN.
Compatible fixture packaging patch over signed v0.2.1, not production readiness.

The default development cache now uses public Wolfi Valkey 9.1.2, authenticated
through its signed Chainguard index and exact Linux/amd64 platform digest.
Startup requires a current exact-image scan and inventory. Weekly/manual
freshness includes the Wolfi Valkey index. No custom cache build is maintained.

The new fixture has separate custody and preserves the previous fixture for
explicit rollback. Both profiles retain OpenBao-issued credentials, scoped
ACL/key prefixes, memory bounds and fail-closed image admission. Actual tests
cover wrong authentication, denied commands/keys, bounded memory eviction,
kernel restrictions, outage, restart and cache nonpersistence. A bounded RESP
client exists only for fixture qualification; it is not the application adapter.

Native, scratch and Wolfi health probes remain regression profiles. All six
crates are 0.2.2 and publish=false, with no external Rust dependency added.
Heavy image/service checks stay local; GitHub remains code-focused with CodeQL
Default setup. Release metadata automation cannot push or publish crates.

Limits: Linux/amd64 disposable fixture, plaintext loopback cache transport,
finite audit retention and existing private recovery custody. The upstream
Wolfi starter includes bash/shared libraries; their inventory is retained.
The old official Valkey exception applies only to that exact rollback digest.
OpenBao's existing not-affected review expires 2026-11-02. Actual TTL expiry is
still v0.7; application cache adapters, TLS, migration and production recovery
remain later passes. No browser/workbench/recipe/public API behavior is added.
