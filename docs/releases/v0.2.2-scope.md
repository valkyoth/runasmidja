# v0.2.2 — Wolfi Valkey fixture

Status: implementation candidate; maintainer pentest PASS; GitHub and tag pending.
Baseline: signed v0.2.1. Compatible service packaging patch; no new website/API.

## Goal and deliverables

Admit the public Chainguard Wolfi Valkey 9.1.2 image by signed index, immutable
Linux/amd64 leaf and exact-image scan/SBOM. No custom build, private/paid registry
or Rust dependency is required. Retain the previous official exact digest only
as an explicit rollback profile with its existing provenance exception and fresh
mandatory scan. The new image cannot inherit that unsigned exception.

Keep OpenBao-issued ACL delivery, default-user denial, key-prefix and command
permissions, 64 MiB application maxmemory/allkeys-lru, no persistence, read-only
root, nonroot, capability drop, 512 MiB/one-CPU/128-PID fixture limits and loopback
publication. The upstream default entrypoint differs; adapt arguments explicitly
for the two admitted image profiles without adding a shell wrapper or secrets.

Use a new default owned profile `v022-wolfi-valkey`. Earlier vault/database state
is retained untouched. Explicit `RUNASMIDJA_VALKEY_PROFILE=official` plus the old
stack ID selects the rollback image; unknown profile names fail closed. Existing
container image drift still rejects, never triggers replacement or a state reset.
Selection, admission and entrypoint checks enforce the old rollback instance ID.
Require nonzero real/effective host UID and the selected Podman engine rootless
flag before service operations; reject container UID 0 independently.

## Verification

- Signature/index/platform and scanner failure/tampering/UNKNOWN/HIGH/CRITICAL
  rejection; actual server version, Wolfi release metadata and package inventory.
- Fresh OpenBao-first startup and retained restart; initial/denied/sealed vault,
  interrupted startup, credential version reuse and revoked-root behavior.
- Actual auth/default-user/wrong-password, command and foreign-key denials,
  set/get/delete, cache outage/restart and credential/config disclosure checks.
- Inspect effective runtime security/limits and live kernel capability/resource
  state. Configuration checks retain nonpersistence and the memory policy.
- Bound isolated qualification data: at most 1536 cache values of 65,500 bytes, individual
  replies <=64 KiB, <=5000 commands/180 seconds and <192 MiB transfer, child capture <=1 MiB, 180-second child deadline. Prove memory
  remains bounded with actual eviction; do not grant the runtime ACL admin rights.
- Stop the new fixture, start/qualify the retained old profile using the old
  image, then return to the new profile. Preserve both profiles' data/custody.
- Common Rust/no_std/Python tests, audits, freshness, inventories and local runtime
  checks pass. No heavy work is added to automatic GitHub CI.

## Exit criteria and limits

Evidence, release notes and threat/operational documentation accompany the
candidate. Maintainer exact-source pentest and normal release loop are mandatory.
No production cache durability/TLS/HA claim, state migration or publication.
Actual TTL expiry qualification remains v0.7.0; no claims from merely SET EX.
The upstream image includes bash and shared libraries; inventory is disclosed,
not advertised as shell-free. OpenBao Wolfi admission remains the next proposed
patch; v0.3.0 remains the next minor workstream.
