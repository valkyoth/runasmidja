## Goal and deliverables

Only OpenBao-first provisioning of the existing disposable Linux service fixture.
No application SDK/provider admission, browser behavior or public API is added.
The six-crate portable graph remains unchanged; Python owns test orchestration.

Start verified-TLS OpenBao, initialize/unseal, require declarative file audit,
configure KV v2 and separate provisioning/runtime AppRoles. OpenBao issues three
32-byte random passwords encoded as exactly 64 lowercase hex characters. Store
admin/database/cache values at `runasmidja/data/provisioning`, project only
runtime database/cache passwords at `runasmidja/data/runtime`, both version 1.
Use create-only CAS=0; deletion, wrong schema/version and projection mismatch fail.
Scoped provisioning can only read both paths; runtime can only read its path.
Both can revoke their own tokens. Neither may create secrets, use random APIs,
manage policies/mounts or retrieve recovery/root material.

Dependent services start only after both scoped identities successfully retrieve
and validate the same vault versions. Revocation of the initialization root is
confirmed after provisioning/consumer readiness; interrupted runs preserve their
vault/data/custody and resume without replacing credentials. Tokens are revoked
on scope exit; revocation failures fail the operation.

## Profile and bounds

Linux/rootless Podman, local single-share automated recovery, generated RSA3072
vault startup TLS certificate valid 30 days. This key and unseal/authentication
custody are enumerated bootstrap trust anchors; database/cache secrets have no
local generation fallback. Default instance `v02-wolfi-ready`, separate `.local/stacks/v02-wolfi-ready`
and resource names from legacy `.local/stack`/`runasmidja-test-*`. Legacy data is
retained without importing locally generated credentials or resetting/rekeying.
Custody-preserving legacy migration is pending the v0.8 delivery qualification;
using a new profile never attests that the old fixture now satisfies the policy.

Private directories 0700 and files 0600, same-user ownership, no symlink reads;
private metadata maximum 64 KiB. Project/service/instance labels must match
before reusing/stopping containers, networks or volumes. Reused containers must
match the reviewed image reference. Network is private/internal, publications
are fixed loopback ports 15432/18200/16379. Each service has memory 512 MiB,
1 CPU and 128 PIDs; Valkey uses 64 MiB. Complete mount/port/resource fingerprints
and adversarial races between inspect/mutate remain v0.5 qualification.
OpenBao responses maximum 1 MiB; HTTP timeout 10 seconds, readiness polling
90 seconds (individual checks can extend the deadline by their timeout), child
command timeout 180 seconds. AppRole SecretIDs 24 hours, access tokens 15 minutes
with maximum 1 hour; no automatic identity rotation/renewal is claimed.

Child input is capped at 64 KiB, aggregate stdout/stderr at 1 MiB by default,
with concurrent draining/writing and kill/reap on limit/deadline failure.
Public image SBOM capture uses an explicit 16 MiB cap and 900-second deadline.
Container logs rotate at 1 MiB. Live audit uses a 16 MiB tmpfs and snapshots
retain at most two 16 MiB owner-only regular files; a full audit sink can deny
vault service. Audit history is finite and abrupt loss may discard its live tail.
Private writes fsync both file and containing directory; replacement/removal
also sync the parent. Remote vault init and local capture remain non-atomic.

Every startup/reuse/smoke requires exact-digest vulnerability scans and the
reviewed publisher policy. OpenBao's signed index must bind the selected leaf.
Only the original exact PostgreSQL/Valkey unsigned pins have maintainer approval;
the rejected PostgreSQL pin and its 42 findings remain historical. Its authorized
replacement builds official source on a signed Wolfi base, resolves to a local
receipt-bound immutable image ID, and scans clean at the HIGH/CRITICAL threshold.
Every archive config/layer is checked against that ID. Public builds need no
credential and exclude custody from their context. This is a trusted-host fixture,
not an independently reproducible or publisher-signed distributed image.
The runtime omits compiler/Perl/gosu and supports the fixed UTF8/C.UTF-8 profile;
ICU/readline and other optional capabilities are not admitted. No CVE waiver is used.

## Verification and exit

`test_stack.py` covers ordering, outages/denials, create-only issuance, reuse,
tombstones/version/schema/projection failures, scoped-token cleanup, root
revocation checkpoints, ownership/image denials, custody and delivery drift.
`stack_qualification.py` qualifies real TLS OpenBao and dependent services:
empty-state interrupted start, sealed/unavailable/denied vault, partial retry,
root revocation, policy denials, authentication, restart and persistent data.
Real wrong-label container/network/volume and stop denials are tested.
Logs/inspect metadata are scanned in memory for issued credentials, captured
bootstrap root, AppRole SecretIDs, recovery shares and TLS key material; reporting
is count/status only. Run common Rust/no_std/Python gates, optimized Python,
service qualification, freshness, advisory/license checks and current SBOM.

Do not attest pentest PASS from these checks. Stop with source digest/evidence,
notes and limitations for the maintainer's pentest; commit only after their green
result unless they explicitly request a pre-pentest candidate commit. The current
remediation candidate is committed under that explicit request for retest, not
accepted as pentest PASS. Unresolved gaps remain explicit in the handoff and release plan.
Persistent private service-password/ACL delivery copies remain a v0.8 limitation.
Build/release identities are v0.9; SDK admission/rotation, production TLS/HA,
independent encrypted recovery and provider guarantees remain later owners.
