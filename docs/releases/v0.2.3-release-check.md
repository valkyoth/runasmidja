## Release and publishing boundary

The only release workflow is manually dispatched, with `contents: read`, checkout
credentials disabled and a 10-minute metadata job. It runs `check_release.py`,
which performs local file/report/source checks and read-only Git queries. It has
no `git push`, tag creation, `cargo publish`, registry upload or GitHub Release step.
All six workspace crates explicitly disable publishing. No sibling repository or
crate is pushed, published or modified. Version-tag creation requires a separate
explicit maintainer request; a tag does not authorize distribution publication.

Push/PR CI remains Rust/Python/repository/dependency checks and a small native
probe, with a 15-minute job ceiling. Heavy containers, scans and fault suites stay
local. CodeQL remains Default setup, without an advanced workflow. No claim is
made that the pending commits have passed GitHub before the maintainer pushes.

## Accepted limitations

This is a Linux/amd64 development fixture, not the production website/API. Known
path detection is bounded and does not prove arbitrary text nonsensitive or decode
all URI forms. Local assembly trusts the host and is not publisher-signed or
bit-for-bit reproducible. External OpenBao plugins, production TLS/recovery,
durable audit and complete redistribution notices remain unqualified. PostgreSQL
is beta. The exact-image OpenBao UNKNOWN not-affected review expires 2026-11-02.
No severity threshold or expiry was relaxed for release.
