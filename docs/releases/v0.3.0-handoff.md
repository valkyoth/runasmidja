## Limits and handoff

Container/service build/scan/fault suites were not rerun for unchanged inputs.
Their historical evidence is not a new v0.3.0 runtime claim. Unit-test messages
mentioning service readiness come from mocked fixtures, not real services in this
pass. Actual native-probe evidence is listed separately above.

Remote action internals, shell execution, checkout mutations, deliberate policy
changes and trusted host/bootstrap tooling are outside this reference gate.
Local allowlists currently remain empty. Remote commits/digests are immutable
references, not authenticity or safety certificates. Parser restrictions are an
explicit conservative subset, not a general GitHub schema validator.

GitHub CI remains code/dependency-focused with a 15-minute ceiling and CodeQL
Default. Its only added setup is the small hash-pinned parser install; no container
builds, scans or services are added. Release automation is unchanged and does not
push, tag, publish crates or upload images. All crates remain publish=false.

Next: maintainer pentest of this committed candidate, remediate and retest any
findings, then finalize acceptance and let the maintainer push. Wait for green
GitHub and an explicit tag instruction before releasing. v0.4.0 is not started.
