## SAST-001 remediation — maintainer retest required

The review of d5236ec reported one Low global artifact-cache race. Existing
admission checks prevented unauthorized images, but competing builds could
invalidate local receipt/archive publication. A global exclusive lock now spans
all build mutations; shared locks protect coherent reads and the full archive
scan. Automatic builds recheck completed receipts after waiting. The per-stack
lock is still separate. Lock/state custody and release on failure/death are
explicit, and the persistent lock is never deleted.

Seven new tests raise the normal/optimized suite to 162. Real spawned processes
exercise competing direct/automatic builders, concurrent readers, interrupted
publication and writer termination/retry; a separate test verifies the image
gate holds shared read access through scanning and releases it on scanner error.
Heavy subprocess/image operations are mocked in unit tests, while actual file
locking and publication are exercised. Invalid custody subcases cover symlink,
mode, ownership, nonregular and hard-linked lock files. Existing failure/retry
regressions run through the new real lock as well.

Common Rust/no_std gates, cargo deny and fresh 1,290-advisory RustSec audit pass.
The lock-bound OpenBao recipe is rebuilt and freshly scanned. The new image keeps
the exact same executable/base/license; only its recipe label changes. Its
UNKNOWN review is explicitly bound to the new exact image without extending
expiry. Current identities are in the [recipe](../../deploy/podman/openbao/README.md).
Actual official-to-Wolfi retained-vault switching and full service qualification
PASS with the rebuilt image: scoped auth/ACL/SQL, audit exhaustion/recovery,
resource bounds, disclosure/ownership denials, PostgreSQL persistence and its
12 initialization negatives. Live freshness and final whitespace/privacy checks
also PASS. Prior native/scratch/Wolfi probe and PostgreSQL build
evidence remains applicable: their implementation, recipes and binaries are
unchanged. Heavy work stays local, and no production assurance is added.
