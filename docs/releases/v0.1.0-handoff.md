## Exact scope

The maintainer retested remediation commit `ea746eb`; executable code and
dependency graphs remain unchanged during release finalization. The final
source commit/digest are bound in the [assessment report](../../security/pentest/v0.1.0.md).
The candidate source digest is also recorded locally in
`.local/release/0.1.0-candidate.json`, using `scripts/check_release.py`'s existing
digest function. It includes source, configuration, docs and SBOM; build output,
private state, local agent files and pentest reports are excluded. Recompute it
if the candidate changes; the later source commit must match the tested digest.

Deliverables are the EUPL-1.2/Rust 1.99.0 workspace, adapted GitHub/repository
files, five portable crates including the public facade, a Linux development
health probe, code-size/link/policy rejection gates, exact reference provenance,
documentation/release notes and pending release evidence. All six packages are
`0.1.0`, Rust 2024/resolver 3, publish=false; no external runtime dependencies.
The facade and core/ports/HTML/crypto boundaries are always no_std/no alloc with
first-party unsafe forbidden. These leaves reserve APIs; they ship no transforms.

Profiles: native debug/release/all-features; portable crates on
`thumbv7em-none-eabihf` and `wasm32-unknown-unknown`; static Linux musl probe in
a scratch, non-root, read-only Podman container. Wasm compilation establishes
portable compilation only; there is no browser runtime behavior to assess yet.
HTML/crypto boundaries require no Vef/Brynja sibling path or unfinished API.

Numeric scope: executable code files at most 500 lines; probe input buffer
4,096 bytes, sequential connections and two-second per-read/write timeouts.
There is no whole-connection deadline or production HTTP parser/isolation claim.
Only `GET /healthz HTTP/1.1` has a fixed success response; product routes reject.
Native smoke traffic uses the live child's announced OS-selected loopback port;
readiness is bounded to five seconds and 256 bytes, with pre/post liveness checks
and bounded terminate/kill/reap cleanup. The container publishes 18082 on
loopback, runs as 65532:65532, and has 32 MiB memory/16 PID limits. No user
payload, browser persistence, caching, search or transformation is implemented.

Retained service fixtures are disposable local test tooling, not production:
PostgreSQL 19beta4 on 15432, TLS OpenBao 2.7.1 on 18200 and Valkey 9.1.2 on
16379, all published only on loopback. Each service container is limited to
512 MiB, one CPU and 128 PIDs; Valkey's data cap is 64 MiB. Private state is 0700
and credential files 0600. OpenBao tokens have a 15-minute TTL/one-hour maximum,
SecretIDs a 24-hour TTL, and its generated certificate a 30-day lifetime.
Startup readiness is bounded to 90 seconds, helper subprocesses to 180 seconds,
vault replies to 1 MiB and cache bulk replies to 64 KiB. These harness limits
do not qualify future product budgets, production TLS or recovery custody.

Fixture provenance: first-party Rust/Python rejection fixtures; actual local
process/container/service tests; supplied reference bytes checked against
[SHA256SUMS](../reference/SHA256SUMS), including the original ZIP. No crypto,
operation, dataset/model/provider or recipe semantic revision is admitted.

## Known limitations to include in the pentest

- Secret origin/delivery: current scripts generate passwords locally before
  seeding OpenBao and retain private plaintext files. This does not meet the
  new project-wide origin policy. Remediation owners: 0.2.0, then 0.8.0–0.9.0;
  production recovery custody is 0.131.0. No secret-origin PASS is claimed.
- Workflow/graph gates: `.yaml` policy omission and comment-spoofed no_std
  checks are confirmed limitations. Current actual manifests/workflows are
  inspected and compile, but guards do not reject every bypass. Owners:
  0.3.0–0.4.0. No enforcement-hardening PASS is claimed.
- Fixture mutation: reuse checks a scope label; stop and volume/network handling
  lack complete ownership/drift checks. Existing fixture labels/images were
  inspected before this restart; collision/fault qualification remains 0.5.0,
  with concrete minimum ownership prerequisites already required at 0.2.0.
- Valkey smoke accepts EX and deletes immediately; it does not observe actual
  expiry/countdown. Expiration evidence belongs to 0.7.0/0.11.0. PostgreSQL and
  Valkey transports are local-fixture plaintext; production transport is pending.
- Release evidence: the checker validates report metadata/source lineage and
  SBOM presence, not assessor identity or distributed artifact authenticity.
  Owners: 0.10.0 and 0.367.0/0.382.0. Automated success cannot attest pentest PASS.
- GitHub CI, CodeQL Default and repository security settings require actual
  hosted evidence after the maintainer pushes. No remote result is claimed here.

These are disclosed findings with later owners, not pentest acceptance or
permission to ignore a release blocker. The maintainer's assessment decides
whether remediation is required before accepting this foundation candidate.
