# v0.2.3 — Wolfi OpenBao fixture

Status: implementation candidate; maintainer pentest RETEST REQUIRED.
Baseline: signed v0.2.2. Compatible Linux/amd64 development packaging patch.

## Goal and deliverables

Admit a minimal local COPY-only Wolfi image retaining the exact signed upstream
OpenBao 2.7.1 static binary. The commercial packaged image is not publicly
accessible; no paid registry or source toolchain is introduced. Verify signed
index/platform identities for upstream and base, executable hash and ELF ABI,
archive/config/layer integrity and a fresh exact-image vulnerability inventory.
No mutable tag, secret-bearing build context or shell build command is used.
Retain upstream provenance/license information and disclose Wolfi shell/libraries.

Use isolated default fixture v023-wolfi-bao for new cold-start tests. Retain prior
fixture custody. Support explicit official/Wolfi same-version switching of only
the owned vault container with unchanged private config, data and credential
versions. Qualify rollback in the same new fixture before accepting the image.
No production state migration, external plugin qualification or API is added.

## Verification

- Normal/optimized negative tests reject rootful invocation, unreviewed profiles,
  wrong binary hash/dynamic ABI, input/archive drift, scanner failures/findings,
  unowned replacement and broken receipt publication; all code <=500 lines.
- Concurrent direct/automatic builds serialize on one cache-wide lock; shared
  readers retain coherent receipt/archive pairs through scans. Real process
  contention, owner death and interrupted-publication retry tests pass.
- Service evidence transactions serialize scans/publication; image/content-keyed
  snapshots, atomic probe annotations and explicit identity-checked export prevent
  cross-scan or cross-image substitution.
- Fresh vault-first startup, interrupted issuance retry, seal/CA/identity denials,
  root revocation and consumer auth/ACL/SQL behavior pass on actual containers.
- Retained same-version switch in both directions preserves TLS/recovery custody,
  KV/AppRole versions, database data and scoped credentials; no reset or rekey.
- Actual server version/base/binary identity, nonroot/capability/resource state,
  TLS and built-in KV/AppRole/PebbleDB behavior pass. External plugins are absent
  and unqualified; do not claim compatibility from unchanged binary alone.
- Fill only the disposable 16 MiB audit tmpfs to exercise fail-closed audited
  reads and recovery after removing the owned fill file; retain bounded logs.
- Common Rust/no_std gates, native/scratch/Wolfi probe regressions, audits,
  freshness and per-image inventories pass. Heavy work remains local.

## Exit criteria and limitations

Commit the tested candidate and hand it to the maintainer for exact-source
pentest. No tests attest PASS. Trusted local assembly is not distributed signing
or reproducible-source assurance. No waiver of UNKNOWN/HIGH/CRITICAL findings;
any not-affected review must bind the exact image/evidence and expire. The existing
OpenBao review expires 2026-11-02; no automatic renewal or image-wide transfer.
v0.3.0 workflow hardening remains the next minor. Production TLS/recovery and
secret delivery/drift retain their existing later owners.
