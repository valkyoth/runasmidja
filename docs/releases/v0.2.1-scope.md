# v0.2.1 — Wolfi health-probe packaging

Status: implemented and locally qualified; maintainer pentest accepted 2026-10-04.
GitHub checks and explicit tagging remain pending.
Baseline: signed v0.2.0. Compatible packaging patch; no website/API feature.

## Goal and deliverables

Add a Linux/amd64 Wolfi static runtime for the existing health probe. Use the
same Rust 1.99.0 static musl executable as the retained scratch profile. Verify
the public base's signed index/platform leaf, scan exact base and built archive,
bind archive layers/config and copied executable to the image actually tested.
No secrets, credentials, private registry or new Rust dependencies are needed.
Retain notices/Cargo and image SBOMs; monitor the admitted base for drift.

## Bounds and verification

- Build context contains only the static executable and Containerfile; offline
  COPY-only assembly, no RUN instructions or package installation.
- Executable <=16 MiB; archive <=512 MiB; metadata <=1 MiB and <=4096 members
  through the existing archive verifier. Build 180 seconds, scan 900 seconds,
  bounded child output 16 MiB for scans and 1 MiB otherwise.
- Rootless container: UID/GID 65532, read-only root, all capabilities dropped,
  no-new-privileges, 32 MiB memory/no additional swap, 16 PIDs, one CPU.
- OS-selected loopback host port, unique captured container ID/ownership label;
  no replacement/deletion of existing fixtures or mutation of service data.
- Native, scratch and Wolfi health/route/method checks agree. Exact executable
  hash, image/user/limits/ownership and running-state checks precede HTTP tests.
- Reject bad provenance, scanner errors/findings, changed archive/executable,
  resource/identity/ownership drift and failed readiness; cleanup only the
  captured owned container. Unit negatives and actual runtime evidence required.

## Exit criteria and exclusions

Common Rust/Python/no_std gates, dependency audits, freshness, actual three
execution profiles, exact-image scans and resource checks pass locally. Heavy
work remains outside push/PR CI. Run the maintainer's exact-source pentest;
NOT RUN is not PASS. Then follow the usual commit/push/GitHub/tag loop.

Native serial slow-client limitations remain; this is not a production server.
Valkey/OpenBao Wolfi changes are separate proposed v0.2.2/v0.2.3 passes. Fluxheim
starts at v0.11.0. No state migration or distributed image publication occurs.
