## Implemented

- Optional Wolfi static health-probe image, public signed base/index/platform
  pins, COPY-only assembly using the locked Rust 1.99.0 musl executable.
- Exact-image scan plus archive config/layer binding before execution; executable
  copied from the created image must match the built artifact's SHA-256.
- Unique owned container identity, OS-selected loopback publication, requested
  nonroot/read-only limits, live kernel memory/swap/PID/CPU/capability and
  no-new-privileges checks; health and forbidden-route/method verification.
- Source/binary/archive/image qualification record in private local evidence;
  public base/image inventories with package licenses and application hash.
  The scanner inventory and appended first-party component are distinguished.
- Weekly/manual static-base freshness; retained native/scratch profiles.
  No container/service job was added to GitHub; CodeQL stays Default setup.

## Limits and next step

This is still a serial development probe with the existing slow-client limit,
not a production API or untrusted job sandbox. Linux/amd64 rootless Podman with
local host `/proc`/cgroup v2 access is the admitted profile; remote-engine hosts
are not qualified. Scanner OS inventory is separate from Cargo dependency
inventory. The existing OpenBao review expires 2026-11-02. No vault/cache image
migration, credentials, new Rust dependencies, external publication or CI-heavy
job is introduced. Each source file remains below 500 lines.

The maintainer has accepted this candidate with no actionable findings. Full
release checks were repeated; the [assessment](../../security/pentest/v0.2.1.md)
records final artifact identities and the distinction between supplied SAST and
maintainer acceptance. Let the maintainer push, await GitHub and obtain explicit
tag authorization. Do not start another version during that loop.
