# v0.3.0 — Workflow reference policy

Status: implementation candidate; developer checks pass; maintainer pentest NOT RUN.
Baseline: signed v0.2.3. Next minor: v0.4.0 feature/target graph admission.

## Goal and boundaries

Replace text matching with structural YAML admission for `.github/workflows/*`
using both `.yml` and `.yaml`. Validate executed step/job references, including
quoted keys/values, flow mappings and block scalars. Comments, names, environment
values, inputs and shell text are not action references. Keep CodeQL Default and
lightweight CI; no production Rust behavior or container qualification is added.

Remote actions and reusable workflows require full 40-character commit IDs.
Container references require SHA256 digests. Same-repository local composite
actions and reusable workflows require explicit reviewed paths, existing regular
files, and recursive validation. Other local action runtimes are not admitted.
Expressions, ambiguous YAML and unsupported reference forms fail closed.

## Resource profile and verification

Per YAML file: 128 KiB, 40,000 tokens, 20,000 parser events, depth 40. Per repository: 128 workflow
or referenced action documents, 32 local reference levels. No aliases, anchors,
explicit tags, directives, duplicate keys, merge keys or multiple documents.
These deliberate restrictions bound parsing and avoid parser-dependent meaning.

Tests must exercise both suffixes, plain/quoted/block/flow forms, malformed and
dynamic values, duplicate/alias/tag ambiguity, local traversal/symlink/cycle and
transitive bypasses, digest pins and contextual CodeQL checks. Test real repository
admission through the common gate; run optimized Python, Rust/no_std, dependency
checks and upstream freshness. Record reviewed upstream syntax and tooling pins.

## Exit criteria

The above implementation and negative regressions pass; README, security controls,
release notes and source evidence agree. Stop for the maintainer's exact-candidate
pentest; NOT RUN remains blocking until explicit green acceptance. Commit locally,
let the maintainer push, wait for GitHub and tag only when requested.
